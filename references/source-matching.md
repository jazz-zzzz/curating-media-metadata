# Source Matching Guide

## match_method 分类

| 方法 | 含义 | 何时使用 |
|---|---|---|
| `order_assumed` | 按顺序推定，未做标题匹配 | 本地集数 = 源集数，位置吻合，没有矛盾证据 |
| `title_exact` | 标题精确匹配 | 文件名或现有元数据中的标题与源条目标题一致 |
| `title_fuzzy` | 模糊标题匹配 | 标题部分匹配但需要归一化（去标点、去空格、翻译等价） |
| `manual` | 人工指定 | 用户直接指定该文件的源条目 |
| `gap` | 源无对应条目 | 本地有此集但在线源没有（Special/OVA/未收录） |

## 多源对比策略

步 2 必须：

1. 对每个源拉取完整剧集列表（aired/DVD/absolute/特别篇）
2. 对比维度：
   - 总集数
   - 季数 + 每季集数
   - 特别篇数量 + 位置
   - 各集标题列表
3. 选择与本地结构匹配度最高的源 + 顺序组合
4. 如果多个源匹配度接近，优先用户熟悉的源

## 匹配规则

- 从文件名中解析季/集号的结构 token（通常是第一个 `S01E01` 或 `1x01` 位置）
- 不要让标题文本中出现的 `& 1x18 - ...` 覆盖真正的结构集号
- 合并集：存储标题为 `故事 A / 故事 B`，简介用 `A 段：... B 段：...`
- 拆分源冲突：本地分组是权威，将在线源条目映射到本地分组中
- 搜索窗口：±3 集。超出此范围必须标记为 `needs_review` 且 `match_method=manual`

## 审核行标记条件

`needs_review=true` 当：

- `match_score < 0.7`
- `match_method != order_assumed`
- 源条目缺少标题或简介
- 文件是合并集但源条目是拆分的（或相反）
- 简介缺失需要翻译或兜底
- 用户提供的修正覆盖了自动匹配
